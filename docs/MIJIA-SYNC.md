# 米家 S200 体重同步

2.1.46 更新：修正网页登录区域尺寸；显示加载进度、网络/HTTP/证书/渲染错误和 25 秒超时，并提供重新打开入口。网页可见后才能完成登录，仍以实际登录 Cookie 校验。此版本尚未完成真实账号和 S200 端到端验证。

FitLog 2.1.26 提供实验性的米家云端体重读取，适配目标为 `yunmai.scales.ms106`。本地构建通过不代表已完成该设备的真实账号验证。

## 使用

1. 在米家中绑定 S200、创建自己的成员，并确认历史记录中已有称重结果。
2. 在 FitLog 的「设置 → 小米 S200 → 连接」选择与米家相同的地区。
3. 在小米网页完成登录及验证码验证，然后点击顶部「完成登录」。
4. 选择自己的成员，应用读取最新体重；也可点击「立即同步」。不会默认选择家庭成员。
5. 开启「打开应用时自动同步」后，应用回到前台时检查，前台期间每 5 分钟检查一次。应用关闭后不持续轮询。数据必须先由米家或蓝牙网关上传云端。

同步更新「我的体重」，供之后开始的自重训练使用。进行中或历史训练不重算。只导入比当前体重更新的有效称重，防止重复和旧云端记录覆盖新的手动体重。本版不提供体重历史图表。

## 账号与错误处理

密码与验证码只在小米登录页填写，不保存到 FitLog。完成登录后，网页登录 Cookie 被清除；仅保存后续读取所需的服务会话。服务会话和成员选择使用 Android Keystore 的 AES-GCM 密钥加密，存入应用的 no-backup 目录，避免凭据进入设备备份。断开连接会移除本地连接信息，保留当前体重。

登录过期需要重新连接。网络、响应解析或接口失败时显示状态，不将失败值写为体重。接口可能随小米服务变化；没有真机账号时不能承诺 ms106 返回数据。

## 实现依据与校验

只调用登录、设备列表、成员列表和体重查询接口，不修改米家数据。接口请求格式参考 MIT 项目 [dolczykk/xiaomi-scale-mcp](https://github.com/dolczykk/xiaomi-scale-mcp)，许可保存在应用打包的 `assets/THIRD-PARTY-NOTICES.txt` 中。

`checks/MiCloudCheck.java` 在 JVM 上验证生产代码的 RC4-drop1024 与 JCE 独立实现一致、请求签名、成员隔离、称重时间转换、无效数据拒绝和覆盖规则。需生产构建目录、Kotlin 标准库及 `org.json` 的 JVM 实现，后者仅用于检查，不增加应用依赖。

真机验收：登录与验证码、地区不匹配、本人及其他成员、无称重记录、一次新称重、重复同步、手动体重优先、登录过期、断开后重启、返回前台及前台定期同步。

网页登录回调与 Cookie 生命周期参考 [Android WebViewClient](https://developer.android.com/reference/android/webkit/WebViewClient) 和 [CookieManager](https://developer.android.com/reference/android/webkit/CookieManager) 官方文档。外部浏览器的登录 Cookie 不由应用内 WebView 共享，因此没有添加无法回传登录状态的“浏览器登录”伪入口。
