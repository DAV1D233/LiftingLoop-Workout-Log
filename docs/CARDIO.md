# 有氧重构 · 2.1.78 / 89

## 使用流程

- 连续运动：自由计时、目标时长、目标距离。只记录一次，不要求轮数或休息。时间目标达成后仍可继续，用户结束时确认实际数据。
- 间歇训练：按时间、按次数或按距离；设置轮数、每轮运动量和轮间休息。计时模式自动切换运动/休息，计次/距离模式点击完成一轮。支持提前完成本轮、跳过休息、暂停/继续和提前结束。
- 完成项目后统一确认一次，目标距离预填为实际距离，可直接保存或修改；无目标时距离可不填。跑步/骑行/快走采用公里输入，泳池等采用米。分钟、秒自动带入有效运动时长，均可修正。
- 泳池游泳保留泳池长度、泳姿和单程趟数，趟数加减同步实际距离。
- 专用深色有氧页面突出时间、阶段、完成轮数、暂停和结束。休息最后 3 秒只显示放大数字。打开设置/讲解先暂停，关闭后手动继续。
- 力量和有氧可在同一计划中混合；有氧确认后才开始下一项目的计时。已有历史记录继续兼容。历史动作卡片突出有效运动时间、距离和有数据时的配速/均速，多个有氧段显示轮数。

## 状态和保存

`CardioEngine` 使用绝对阶段边界，不依赖 UI 定时器逐秒累加。延迟 tick 可以补齐已到期的运动/休息阶段，最后一轮停在确认状态；不会直接用预填目标生成数据库记录。

`WorkoutSession` 新增可选暂停起点、累计暂停、当前段暂停及待确认项目索引。`SessionStore` 将这些字段与训练检查点一起提交；旧检查点缺省为未暂停。`CardioTarget.training` 区分 continuous/interval/auto，旧计划自动按轮数及计次方式兼容。字段保存在现有 JSON 内，无 Room 表结构迁移。

休息自然结束后从休息截止点开始下一段，修复旧逻辑把休息加入运动时长的问题。暂停冻结运动与休息，恢复后平移截止点，累计时长排除暂停。待确认数据也写入检查点，确认后才事务性保存或继续下一动作。当前项目完成后的回退历史清空，避免下一力量动作撤销到有氧之前而丢掉确认结果。

提前减少轮数会保留提前结束标记；新的有氧确认流程按实际时间/距离/次数判断目标，不把未达目标显示为“目标达成”。保存失败保留结束检查点，页面可重试，唯一会话键避免重复入库。

## 范围与限制

本版没有 GPS、自动计步/距离测量、心率、热量估算或设备连接；距离来源为用户确认的预填/输入值。不能根据目标距离声称实时配速。配速/均速仅在实际时间、距离均大于零时计算。

后台和重开依据保存的时间点恢复，不使用持续计数来推断时长。没有新增常驻前台服务、唤醒锁或精确闹钟，因此系统休眠或终止进程期间的声音/振动提示不保证准点；回到 App 后补齐阶段，停在最终确认，不重复保存。长时间锁屏和厂商省电行为需单独实机验证。

不改变框架或构建版本，没有新增运行时依赖。
